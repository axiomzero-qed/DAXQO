# DAXQO V0.4 安装、权限与远程控制 / DAXQO V0.4 Installation, Permissions, and Remote Control

> 本指南描述 V0.4 的安装与操作流程。部分手机端验收已完成；完整邮件远程控制闭环仍在进行中。下表区分已通过与待测项目，未列为通过的项目不应视为已验证。

> This guide describes the V0.4 installation and operation flow. Some phone-side checks have passed; the complete email remote-control loop is still in progress. The table distinguishes passed from pending items, and unmarked items must not be treated as verified.

## 安装与本机控制 / Installation and on-device control

V0.4 沿用已有 StepX Linux 容器和已运行的 supervisor，不迁移或重建现有运行时。安装 V0.4 APK 后，从 DAXQO App 中使用手机控制功能。DAXQO 不能启动或唤醒厂商 Linux 容器；容器和服务必须已经在线。Termux/proot 环境及中兴旧机迁移不属于本轮范围，计划在 V0.5 处理。

V0.4 reuses the existing StepX Linux container and running supervisor; it does not migrate or rebuild the existing runtime. Install the V0.4 APK, then use phone control from the DAXQO app. DAXQO cannot start or wake the vendor Linux container; the container and service must already be online. Termux/proot environments and migration of the older ZTE phone are out of scope for this release and are planned for V0.5.

辅助功能默认关闭。需要控制手机时，先在 Android 系统设置中由用户手动开启 DAXQO 的辅助功能，再返回 App 并点击开始控制。用户可按需配置通知权限、电池后台运行设置及桌面快捷入口。

Accessibility is off by default. To control the phone, the user must manually enable DAXQO accessibility in Android system settings, return to the app, and tap Start Control. The user may configure notification permission, background battery settings, and a home-screen shortcut as needed.

截图能力要求 Android API 30 或更高版本。锁屏时，App 只尝试点亮屏幕，仍需用户本人解锁；遇到安全屏幕时不会绕过系统保护。

Screenshot capability requires Android API 30 or later. While the phone is locked, the app only attempts to wake the screen; the user must unlock it. System protections are not bypassed on secure screens.

当控制流程检测到敏感页面时，控制会暂停并等待用户手动继续。但敏感页面检测和任务指令都不能保证识别或硬拦截所有敏感语义，不应视为完整的安全边界或百分之百准确。

When the control flow detects a sensitive page, control pauses and waits for the user to resume it manually. Sensitive-page detection and task instructions cannot guarantee detection or hard blocking of every sensitive semantic case, and must not be treated as a complete safety boundary or as 100% accurate.

## 本机 MCP 接口 / Local MCP interface

Android MCP server 使用 stdio 启动，例如 `python backend/android_mcp_server.py --state-dir APP/state --port 18883`。控制桥固定访问 `127.0.0.1:18883`；服务与后端共享安装目录中的私有 capability，不向局域网或公网开放。
The Android MCP server is launched over stdio, for example with `python backend/android_mcp_server.py --state-dir APP/state --port 18883`. The bridge connects to `127.0.0.1:18883`; it shares a private capability in the installation directory with the backend and is not exposed to the LAN or public internet.

Harness 仅预授权自有 `daxqo_android` 的 `android_status`、`android_observe`、`android_action` 三项工具，其他工具保留默认确认策略。预授权不会开启原生手机控制开关，也不会解除锁屏或敏感页面暂停。配置格式参考[官方 MCP 配置说明](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。

The harness preauthorizes only `android_status`, `android_observe`, and `android_action` from its own `daxqo_android` adapter. Other tools retain their default confirmation policy. This does not enable the native control switch or clear lock-screen and sensitive-page pauses. See the [official MCP configuration reference](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) for the configuration format.

## 邮箱远程控制 / Email remote control

在 DAXQO 的“远程”设置页配置邮件账户。服务使用 IMAP over SSL 的 `993` 端口和 SMTP over SSL 的 `465` 端口。163 邮箱需要使用 IMAP/SMTP 授权码；邮箱大师的登录密码不代替邮件客户端授权码。邮件密码保存在手机 Linux 私有配置中。

Configure the mail account in DAXQO's Remote settings. The service uses IMAP over SSL on port `993` and SMTP over SSL on port `465`. A 163 mailbox requires its IMAP/SMTP authorization code; the Mail Master sign-in password is not a substitute for that authorization code. The mail password is stored in private configuration on phone Linux.

添加可信联系人后，DAXQO 会生成该联系人的随机专属 HMAC 配对密钥。配对密钥只在添加时显示一次；通过安全渠道交给对应联系人。联系人还需使用此密钥对邮件命令签名。可信联系人获得的是 Harness 权限，并非隔离沙箱。邮箱已连接并不代表任何联系人已获授权，联系人启用也必须由用户手动完成。停用联系人会阻止其新命令及后续回信，但不会自动停止已经运行的任务；需要时必须显式发送 `stop`。

After a trusted contact is added, DAXQO generates a random, dedicated HMAC pairing key for that contact. The key is shown only once when the contact is added; deliver it to that contact through a secure channel. The contact must sign email commands with this key. A trusted contact receives Harness permissions, not an isolated sandbox. Connecting a mailbox does not authorize any contact, and enabling a contact requires an explicit user action. Disabling a contact blocks its new commands and subsequent replies but does not stop tasks that are already running; send an explicit `stop` when needed.

远程邮件支持 `submit`、`status` 和 `stop` 操作。请求使用 600 秒时间窗和 nonce 防止重放；联系人只能查询或停止由同一联系人发起的任务。DAXQO 的结果回复带有签名。

Remote email supports `submit`, `status`, and `stop` actions. Requests use a 600-second time window and a nonce to prevent replay. A contact may query or stop only tasks started by that same contact. DAXQO result replies are signed.

## 联系人侧 MCP 配置 / Contact-side MCP configuration

联系人可通过 `scripts/remote_email_mcp.py` 使用 MCP 工具 `remote_submit`、`remote_status` 和 `remote_stop`。配置文件应放在源码目录之外的私有路径，权限设为仅当前用户可读写，例如：

The contact can use the MCP tools `remote_submit`, `remote_status`, and `remote_stop` through `scripts/remote_email_mcp.py`. Store its configuration outside the source tree in a private path with read/write access limited to the current user, for example:

```sh
chmod 600 /private/path/remote-email.json
python scripts/remote_email_mcp.py --config /private/path/remote-email.json
```

示例配置只使用中性占位值；请替换为实际邮件账户、联系人地址和配对密钥，不要把真实值提交到源码仓库：

The sample configuration uses neutral placeholders only. Replace them with the actual mail account, contact address, and pairing key; never commit real values to the source repository:

```json
{
  "deviceEmail": "device@example.com",
  "contactEmail": "contact@example.com",
  "contactSecret": "REPLACE_WITH_CONTACT_PAIRING_SECRET",
  "smtpHost": "smtp.example.com",
  "smtpPort": 465,
  "username": "contact@example.com",
  "password": "REPLACE_WITH_MAIL_AUTHORIZATION_CODE"
}
```

SMTP 接受发送请求只表示邮件服务接收了邮件，不代表手机已接收命令、任务已经启动或任务已经完成。请通过 `remote_status` 或带签名的结果邮件确认任务状态。

SMTP accepting a send request means only that the mail service accepted the message. It does not prove that the phone received the command or that a task started or completed. Confirm task state with `remote_status` or the signed result email.

## 已知限制与验收状态 / Known limitations and acceptance status

远程邮件依赖手机 Linux 服务在线、邮件服务器可用、授权码有效及联系人配对配置正确；它不能唤醒厂商 Linux 容器。锁屏解锁、安全屏幕处理、辅助功能敏感页暂停和页面识别均受 Android 版本与应用行为影响。可信联系人拥有 Harness 级访问能力，不是沙箱隔离；敏感页面检测与自然语言任务指令无法保证覆盖或拦截所有敏感语义。停用联系人不会自动停止其已运行任务，必须显式请求停止。

Email remote control depends on the phone Linux service being online, the mail server being available, a valid authorization code, and correct contact pairing; it cannot wake the vendor Linux container. Unlocking while locked, secure-screen handling, pausing on sensitive pages, and page recognition depend on Android version and app behavior. Trusted contacts have Harness-level access, not sandbox isolation; sensitive-page detection and natural-language task instructions cannot guarantee coverage or blocking of every sensitive semantic case. Disabling a contact does not stop its already-running tasks; an explicit stop request is required.

实测发现网易 IMAP 的 `SEARCH SUBJECT` / `FROM` 可返回空结果，而邮件实际存在。轮询因此使用 `ALL` 获取 INBOX 最新 100 封，在客户端筛选 `DAXQO/1` 主题并有界读取正文，再执行 From、HMAC、时间窗与 nonce 校验；不依赖未读状态。自发自收的首封测试信因该兼容问题未在有效时间窗内执行，不计为闭环通过。

Real-device testing found that NetEase IMAP `SEARCH SUBJECT` / `FROM` can return no matches for an existing message. Polling therefore uses `ALL` to inspect the latest 100 INBOX messages, filters `DAXQO/1` subjects locally, reads bounded bodies, and then checks From, HMAC, timestamps, and nonce deduplication without relying on unread flags. The initial self-addressed message was not executed within its time window because of this compatibility issue and does not count as a passed end-to-end test.
