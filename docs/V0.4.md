## 安装与本机控制 / Installation and on-device control

V0.4 沿用已有 StepX Linux 容器和已运行的 supervisor，不迁移或重建现有运行时。安装 V0.4 APK 后，从 DAXQO App 中使用手机控制功能。DAXQO 不能启动或唤醒厂商 Linux 容器；容器和服务必须已经在线。Termux/proot 环境及中兴旧机迁移不属于本轮范围，计划在 V0.5 处理。

V0.4 reuses the existing StepX Linux container and running supervisor; it does not migrate or rebuild the existing runtime. Install the V0.4 APK, then use phone control from the DAXQO app. DAXQO cannot start or wake the vendor Linux container; the container and service must already be online. Termux/proot environments and migration of the older ZTE phone are out of scope for this release and are planned for V0.5.

辅助功能默认关闭。需要控制手机时，先在 Android 系统设置中由用户手动开启 DAXQO 的辅助功能，再返回 App 并点击开始控制。用户可按需配置通知权限、电池后台运行设置及桌面快捷入口。

Accessibility is off by default. To control the phone, the user must manually enable DAXQO accessibility in Android system settings, return to the app, and tap Start Control. The user may configure notification permission, background battery settings, and a home-screen shortcut as needed.

STEPX Neo 还需单独允许“锁屏显示”：系统设置 → 应用信息 → 达氙 DAXQO → 权限管理 → 锁屏显示（在锁屏上显示界面）。没有此权限时，即使手机未设密码，StepOS 也会拒绝官方解锁请求。仅在用户同意后开启；DAXQO 不会自动修改该系统开关。

STEPX Neo additionally requires “Display views on lock screen”: System settings → App info → DAXQO → Permissions → Lock-screen display. Without this permission, StepOS rejects the official dismissal request even when no device password is set. Enable it only with owner consent; DAXQO does not automatically change this system switch.

截图能力要求 Android API 30 或更高版本。用户授权后，开发者通过正常系统 GUI 开启 DAXQO 的“锁屏显示”权限，系统 appops 为 `STEP_ACTIVITY_ON_LOCKED_SCREEN: allow`。2026-10-23 01:06 原生唤醒验收、01:07–01:08 Harness 自主计算任务均通过，详见验收表。安全锁/生物识别、SIM 限制及电池优化行为仍需单独验证。

Screenshot capability requires Android API 30 or later. With owner authorization, the developer enabled DAXQO's “Display views on lock screen” permission through normal system UI; appops reports `STEP_ACTIVITY_ON_LOCKED_SCREEN: allow`. Native wake acceptance passed at 01:06 China Standard Time on 2026-10-23, followed by a successful autonomous Harness calculator task at 01:07–01:08; see the acceptance table. Secure lock/biometric, SIM restrictions, and battery-optimization behavior remain separately untested.

只读观察通常无需逐项确认，也不会因为页面属于系统授权页面就一概禁止读取。检测到需要本人处理的安全暂停（`needsUser`）时，仍须本人在手机上继续；这是页面安全暂停，与可远程处理的单次操作审批不同。敏感页面检测和任务指令不能保证识别或硬拦截所有敏感语义，不应视为完整安全边界。

Read-only observation normally needs no per-action confirmation, and system authorization pages are not categorically blocked from reading. A safety pause marked `needsUser` still requires the owner to continue on the phone; this is distinct from a one-time operation approval that can be handled remotely. Sensitive-page detection and task instructions cannot guarantee coverage or blocking of every sensitive semantic case, so they are not a complete safety boundary.

## 手机授权模式与单次审批 / Phone permission modes and one-time approvals

手机控制原生页提供 `confirm`（默认）和 `full` 两种模式。`confirm` 下，敏感写操作会等待一次性批准或拒绝；`full` 只表示允许 DAXQO 直接尝试系统允许的操作，不会提升 Android 权限、授予系统签名权限或绕过锁屏。网页只显示当前模式，不提供模式切换；请在手机顶栏“手机控制”页切换。只读观察通常不需批准；系统授权页面不再作为一类页面一律禁读。

The native Phone Control page offers `confirm` (default) and `full`. In `confirm`, a sensitive write waits for a one-time approval or denial. `full` only lets DAXQO directly attempt actions permitted by Android; it does not elevate Android permissions, grant signature-level permissions, or bypass the keyguard. The web UI displays the current mode but cannot change it; use Phone Control in the app's top bar. Read-only observation normally needs no approval, and system authorization pages are not blanket-blocked from reading.

每项待批动作绑定具体动作、参数和页面，有效期 10 分钟。带节点的文本输入执行前会校验当前 UI 快照；审批身份排除易变的 `snapshotId`，仍绑定节点、文本、目标和页面；未指定节点时会额外绑定输入焦点。临时运行时窗口 ID 不作为绑定条件。批准只授权这一次，重放或过期请求会被拒绝。可在 DAXQO 审批卡或可信邮箱中批准/拒绝；批准后原任务自动继续，不需要用户代替手机执行点击。任务状态 `waiting_approval` 表示等待确认，不代表完成；`blocked_system` 表示受到系统限制。邮件确认必须在正文首行写 `确认 <UUID>` 或 `拒绝 <UUID>`。若且仅若当前恰好只有一项有效待确认，可在正文首行单独写 `确认`。不能只用邮件主题确认，以免引用内容造成误授权。原有联系人身份、DKIM、时间窗和 nonce 防重放校验保持不变。

Each pending action is bound to its action, parameters, and page for 10 minutes. Node-based text input validates the current UI snapshot before execution. Approval identity excludes the volatile `snapshotId` while retaining node, text, target, and page binding; input without a node also binds the input focus. A transient runtime window ID is not part of the binding. Approval authorizes that action once; replayed or expired requests are rejected. Approve or decline in the DAXQO approval card or from a trusted mailbox. Approval automatically resumes the original task; the user does not have to perform the phone tap themselves. `waiting_approval` means waiting for a decision, not completed; `blocked_system` means the system blocked the action. Email decisions must be the exact first body line `确认 <UUID>` or `拒绝 <UUID>`. A bare `确认` is accepted only when exactly one valid request is pending. The subject alone is never a decision, preventing quoted text from authorizing an action. Existing contact identity, DKIM, time-window, and nonce replay checks remain in force.

## 本机 MCP 接口 / Local MCP interface

Android MCP server 使用 stdio 启动，例如 `python backend/android_mcp_server.py --state-dir APP/state --port 18883`。控制桥固定访问 `127.0.0.1:18883`；服务与后端共享安装目录中的私有 capability，不向局域网或公网开放。
The Android MCP server is launched over stdio, for example with `python backend/android_mcp_server.py --state-dir APP/state --port 18883`. The bridge connects to `127.0.0.1:18883`; it shares a private capability in the installation directory with the backend and is not exposed to the LAN or public internet.

Harness 仅预授权自有 `daxqo_android` 的 `android_status`、`android_observe`、`android_action` 三项工具，其他工具保留默认确认策略。预授权不会开启原生手机控制开关，也不会清除安全锁凭据要求或敏感页面暂停。配置格式参考[官方 MCP 配置说明](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。

The harness preauthorizes only `android_status`, `android_observe`, and `android_action` from its own `daxqo_android` adapter. Other tools retain their default confirmation policy. This does not enable the native control switch or remove secure-keyguard credential requirements or sensitive-page pauses. See the [official MCP configuration reference](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) for the configuration format.

厂商 `android-abilities` 的调用链、只读实测及可复用边界，见 [Android 能力研究](android-capabilities.md)。 / See [Android capabilities research](android-capabilities.md) for the vendor call path, read-only device check, and reuse limits.

## 邮箱远程控制 / Email remote control

在 DAXQO 的“远程”设置页配置邮件账户。服务使用 IMAP over SSL 的 `993` 端口和 SMTP over SSL 的 `465` 端口。163 邮箱需要使用 IMAP/SMTP 授权码；邮箱大师的登录密码不代替邮件客户端授权码。邮件密码保存在手机 Linux 私有配置中。

Configure the mail account in DAXQO's Remote settings. The service uses IMAP over SSL on port `993` and SMTP over SSL on port `465`. A 163 mailbox requires its IMAP/SMTP authorization code; the Mail Master sign-in password is not a substitute for that authorization code. The mail password is stored in private configuration on phone Linux.

邮件身份验证依赖 `dkimpy` 和 `dnspython`。在已有 Linux APP 中运行安装工具；默认目标是 `~/phone-harness/runtime/mail-libs`，也可用 `--app` 指定其他 APP。工具只写入该 APP 私有目录，不执行完整 Linux 安装、不修改全局 Python 或厂商环境，也不会自动重启服务。成功后需手动重启 DAXQO 后端。目标 Python 环境需已有 `pip` 和可用的构建支持（例如 `setuptools`）；工具不会自动安装全局构建工具。

Email identity verification uses `dkimpy` and `dnspython`. Run the installer for the existing Linux APP; the default target is `~/phone-harness/runtime/mail-libs`, or use `--app` to select another APP. The tool writes only to that APP-private directory; it does not run the full Linux installer, modify global Python or the vendor environment, or restart services. Restart the DAXQO backend manually after installation. The target Python environment must already have `pip` and usable build support (such as `setuptools`); the tool does not install global build tools.

```sh
python3 scripts/install_mail_deps.py
python3 scripts/install_mail_deps.py --app /path/to/APP
```

添加联系人后，DAXQO 会生成仅供 Agent/MCP 命令配对使用的专属密钥；普通 Gmail 邮件不需要联系人手持该密钥。普通邮件处理需用户单独启用，并仅允许已启用联系人通过独立的邮件身份验证。仅凭发件人地址不能授权。可信联系人获得的是 Harness 权限，并非隔离沙箱。停用联系人会阻止其新命令及后续回信，但不会自动停止已经运行的任务；需要时必须显式发送 `stop`。

After a contact is added, DAXQO generates a dedicated pairing key for Agent/MCP commands only; an ordinary Gmail message does not require the contact to use this key. Plain-email handling must be enabled separately and accepts only enabled contacts whose email identity passes independent validation. The From address alone is not authorization. A trusted contact receives Harness permissions, not an isolated sandbox. Disabling a contact blocks new commands and subsequent replies but does not stop tasks that are already running; send an explicit `stop` when needed.

Agent/MCP 远程命令支持 `submit`、`status`、`stop`、`approve` 和 `decline`，并提供 `remote_approve` / `remote_decline` 审批工具；DAXQO 的结果回复带有签名。普通邮件处理默认关闭，初版仅支持个人 Gmail；启用后只处理启用之后收到、来自已启用联系人且通过 DKIM 邮件身份验证的新邮件，不能仅凭发件人地址或 `Authentication-Results` 授权。签名需覆盖关键 MIME 邮件头；日期不早于启用时间且距当前不超过 24 小时；整封最大 96 KiB，主题与正文合计最多 8000 字。带附件的邮件整封拒绝。任务输入由邮件主题与正文组成；正文为空时仅用主题，合并逻辑的单元测试已通过。敏感手机写操作按手机 `confirm` 模式等待一次审批；收到批准后原任务继续，DAXQO 会在任务完成后向登记邮箱发送人类可读结果。最终真机验收见下表：纯标题邮件创建任务后，Settings App info 页面 Back 触发待批；同一可信邮箱回复“确认”后，原 thread 自行唤醒、消费同一审批并执行一次 Back，未再次审批或重新申请；页面与桌面只读核验后任务完成，最终 Gmail 报告送达。邮件审批格式见上节。联系人身份、DKIM 与防重放策略不变。

Agent/MCP remote commands support `submit`, `status`, `stop`, `approve`, and `decline`, with `remote_approve` / `remote_decline` approval tools and signed DAXQO result replies. Plain-email handling is off by default and initially supports personal Gmail only. Once enabled, it handles only new messages from enabled contacts with a valid DKIM identity; the From address or an `Authentication-Results` header alone is not authorization. The DKIM signature must cover critical MIME headers; the message date must be at or after activation and no more than 24 hours old. The whole message is limited to 96 KiB and the combined subject and body to 8,000 characters. Any message with an attachment is rejected in full. Task input combines subject and body; a truly empty body uses the subject alone, and the merge logic has passed its unit test. Sensitive phone writes wait for one approval under `confirm`; the original task resumes after approval, and DAXQO sends a human-readable result when the task completes. The final device run is recorded below: a subject-only email created a task, and Back on Android Settings App info required approval. After the same trusted mailbox replied `确认`, the original thread woke the phone, consumed the same approval, and performed one Back action without a second approval or renewed request. The page and desktop were verified read-only; the task completed and the final Gmail report arrived. Email decision syntax is described above. Contact identity, DKIM, and replay protections are unchanged.

SMTP 接受发送请求只表示邮件服务接收了邮件，不代表手机已接收命令、任务已经启动或任务已经完成。请通过 `remote_status` 或带签名的结果邮件确认任务状态。

SMTP accepting a send request means only that the mail service accepted the message. It does not prove that the phone received the command or that a task started or completed. Confirm task state with `remote_status` or the signed result email.

开发者发送命令时，请将 `--print-command` 的原始输出作为 UTF-8 `text/plain` 正文发送。不要先解析 JSON 再用普通 JSON 序列化还原字符串；邮件通道可能在 ASCII 空格处插入 CRLF，导致正文成为无效 JSON。已验证将相同签名 payload 中的空格写为 JSON Unicode 转义 `\u0020` 可通过传输；payload 内容与签名保持不变。接收端严格校验，不会修补无效 JSON；手动编辑或邮件客户端硬折行可能导致命令被拒绝。

When sending commands as a developer, use the raw `--print-command` output as a UTF-8 `text/plain` body. Do not parse the JSON and serialize it again with a standard JSON serializer: the mail transport may insert CRLF at ASCII spaces, making the body invalid JSON. Testing confirmed that encoding spaces in the same signed payload as the JSON Unicode escape `\u0020` survives transport; the payload and signature remain unchanged. The receiver validates strictly and does not repair invalid JSON. Manual edits or hard-wrapping by a mail client may cause rejection.

## 手机执行效率 / Phone execution efficiency

V0.4 执行指导：默认使用 compact UI 树，只在需要辨认视觉布局或核验结果时截图。滑动须显式提供 `x1`、`y1`、`x2`、`y2`；`durationMs` 默认 350，合法范围为 50–2000 ms。连续两次滑动没有页面变化时，可调整一次；仍无变化就改用其他路径，避免重复滑动。

文本输入优先一次提交完整 Unicode（包括中文），不要逐键拼拼音。只处理完成任务必需的日常权限；无关弹窗可跳过、稍后处理或拒绝，不重复检查已处理的权限。安装应用时优先选择设备自带应用商店，找不到目标应用时再将应用宝作为末位候选。

以上执行指导不改变 `confirm` / `full` 模式、单次审批或系统权限边界。启动应用时，`args.packageName` 是目标应用，`expectedPackage` 是操作前的当前前台；`open_app` 应省略后者，避免把目标误当当前页面。输入搜索词后需提交搜索，并核验带安装/打开按钮的真实应用条目，不能将联想词列表视为完成。

实测发现网易 IMAP 的 `SEARCH SUBJECT` / `FROM` 可返回空结果，而邮件实际存在。轮询因此使用 `ALL` 获取 INBOX 最新 100 封，在客户端筛选 `DAXQO/1` 主题并有界读取正文，再执行 From、HMAC、时间窗与 nonce 校验；不依赖未读状态。自发自收的首封测试信因该兼容问题未在有效时间窗内执行，不计为闭环通过。

Real-device testing found that NetEase IMAP `SEARCH SUBJECT` / `FROM` can return no matches for an existing message. Polling therefore uses `ALL` to inspect the latest 100 INBOX messages, filters `DAXQO/1` subjects locally, reads bounded bodies, and then checks From, HMAC, timestamps, and nonce deduplication without relying on unread flags. The initial self-addressed message was not executed within its time window because of this compatibility issue and does not count as a passed end-to-end test.

Developer test note: prefer screenshots and read-only status requests while approval is pending.
