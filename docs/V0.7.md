# V0.7.0 手机语音、短信与任务工作区

Android 核心版 V0.7.0，versionCode 17；独立 Android Collector 为 versionCode 18，Motor 为 versionCode 19。XM 与 Standard 共用核心。

## 短信任务

- 默认关闭，可信手机号名单默认为空。使用前先在手机控制设置中授予短信与电话状态权限，并明确选择标记为国内且可用的 SIM 卡槽。界面列出 SIM 卡槽；未知归属与英国卡不可选，不会猜测或采用系统默认短信卡。英国 SIM 不读取。
- 登记可信号码后，需由用户单独启用联系人；支持 11 位中国手机号，也可填写 `+86` 前缀。系统按运营商提供的发件号码与可信名单匹配。此匹配不是 DKIM 等密码学发件人认证。
- 开启后只处理新收到的短信；此前短信不补跑。短信正文作为任务输入。可选自动发送简讯结果，结果以 `DAXQO/RESULT` 开头以避免回信循环。
- 短信任务沿用手机控制当前授权模式，不增加任务接单的逐条确认。部分手机仍会对每条结果短信弹出系统发送确认；无法无人值守回信时可关闭短信回复，任务结果仍可在对话中查看。面板显示权限、SIM 与命令/任务状态，不展示短信正文历史。
- 手机设置入口：**手机控制 → 短信与 SIM 卡**。电脑网页端会提示到手机授权。

真机验收：Neo 与 Redmi K70 均已升级到保留独立 Collector/Motor 的 V0.7（versionCode 19）。两台设备都通过国内 SIM 收到短信，并各自成功执行一项测试任务。Neo 自动发送的结果短信已在 K70 收到，`DAXQO/RESULT` 前缀也被正确忽略。

K70 上的 `com.miui.securitycenter` 会逐条弹出短信发送确认；即使 Android 报告 `SEND_SMS=allow`，仍无法无人值守自动回信。因此 K70 关闭短信结果回复，可信号码仍可提交任务，结果可在 DAXQO 对话中查看。此项限制不代表 K70 自动回信闭环通过。测试未在仓库记录任何电话号码。

## 继承功能

V0.7 延续本机流式中文语音识别、可编辑且不自动发送的语音草稿、每个新对话独立工作区、对话成果文件与授权栅格图预览，以及可信邮箱普通邮件。语音模型质量由小模型决定，界面允许用户修订，不保证语义纠错；DeepSeek 仅在用户发送后接收文本。普通邮件支持 Gmail、QQ 与网易，但仍要求可信联系人预先登记、启用并验证邮件身份。QQ/网易闭环验收以单独测试记录为准。

# V0.7.0 SMS, speech and task workspaces

Android Core V0.7.0 uses versionCode 17. The independent Android Collector uses versionCode 18 and Motor uses versionCode 19. XM and Standard share the core.

## SMS tasks

- SMS control is off by default and the trusted-number list starts empty. Grant SMS and phone-state permissions in Phone Control, then explicitly select a SIM slot identified as eligible domestic service. The UI shows SIM slots; unknown-region and UK SIMs cannot be selected, and the system default SIM is never guessed. UK SIMs are not read.
- Register a trusted number before enabling it. Chinese mobile numbers may use 11 digits or a `+86` prefix. Matching uses the sender number supplied by the carrier; this is not cryptographic sender authentication such as DKIM.
- Only new messages received after enabling are processed; old messages are not backfilled. The SMS body becomes the task input. Optional result texts start with `DAXQO/RESULT` to prevent reply loops.
- SMS tasks follow the current Phone Control authorization mode, without an extra per-message confirmation for task intake. Some phones still show a system confirmation for every result SMS. If unattended replies are unavailable, disable SMS replies; task results remain visible in the conversation. The panel shows permission, SIM, command and task status without displaying SMS body history.
- On the phone, use **Phone Control → SMS and SIM cards**. Desktop web users are directed to grant authorization on the phone.

Real-device acceptance: Neo and Redmi K70 both upgraded to V0.7 (versionCode 19, retaining the independent Collector/Motor). Both received SMS through domestic SIMs and each successfully ran one test task. Neo automatically sent a result SMS that arrived on K70; the `DAXQO/RESULT` prefix was correctly ignored.

On K70, `com.miui.securitycenter` displays a confirmation for each outgoing SMS even when Android reports `SEND_SMS=allow`, so unattended result replies are not available. SMS replies are disabled on K70; trusted numbers can still submit tasks, and results remain available in DAXQO conversations. K70 unattended reply delivery is not considered passed. No phone numbers are recorded in the repository.

## Inherited features

V0.7 carries forward local streaming Chinese speech recognition, editable speech drafts that are never sent automatically, separate workspaces for new conversations, conversation artifact files and authorized raster-image previews, and trusted ordinary email. Recognition quality depends on the small model; users can edit the draft, but semantic correction is not guaranteed. DeepSeek receives text only after the user sends it. Ordinary email supports Gmail, QQ and NetEase and still requires trusted contacts to be registered, enabled, and email identity verified. QQ/NetEase end-to-end acceptance should follow its separate test record.
