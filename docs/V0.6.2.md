# V0.6.2 本地语音草稿 / Local voice drafts

核心 Android 版本为 **0.6.2，versionCode 14**。Standard 与 XM 共用核心源码。可选 Android Collector（versionCode 15）和 Motor（versionCode 16）来自各自独立仓库，可作为原生扩展组合使用。

The Android Core is **0.6.2, versionCode 14**. Standard and XM share the core source. Optional Android Collector (versionCode 15) and Motor (versionCode 16) come from their independent repositories and can be included as native extensions.

## 中文

- APK 内含约 **25 MB** 本地语音模型权重。语音识别在设备本机运行，无需 ASR 账号，也无需联网进行识别；麦克风权限仍为必需条件。
- 长按语音按钮开始录音，松开后定稿。识别期间显示累计临时全文，后续 partial 会替换前一版文字；用户可继续修改。定稿只回填到草稿，不会自动发送。用户编辑草稿、切换任务、取消或离开页面后，迟到的识别结果不会覆盖现有内容。
- 识别质量取决于随包小模型，可能出现错词或漏词。界面允许用户修订临时文字，但不保证模型能按语义自动纠错。DeepSeek 只在用户主动发送草稿后接收文本并理解任务；语音音频不会作为任务输入直接发送给 DeepSeek。
- 首次构建会按构建脚本固定的资源版本下载 AAR（约 49 MB）及模型归档（约 21 MB），并缓存到 `DAXQO_VOICE_CACHE` 指定的位置。此构建期下载不代表运行时识别需要网络。
- GUI 工作区成果卡片、授权栅格图片预览、文件打开行为与远程邮件附件边界继续沿用 [V0.6.1 记录](V0.6.md)；V0.6.1 的设备失败记录作为历史保留，不代表本版本的麦克风结果。

### 触屏操作与任务工作区

- 安卓麦克风按钮为 48×48 CSS 像素，录音状态提示使用浮层，长按、加载、临时文字增高、结束或取消时不会顶动录音键；安卓隐藏“Enter 发送”提示，桌面仍保留快捷键提示。
- 新任务使用 `workspace/tasks/<任务 UUID>/`。同一对话的继续、恢复和子任务沿用该任务目录；邮件与定时任务同样通过统一任务入口分配目录。任务详情提供“本任务文件”，全局文件页仍可浏览全部。
- 上传原件保留在导入暂存区，任务使用其 `inputs/` 副本；成果链接、图片预览和邮件附件按该任务目录解析，同名输出不会取到另一个新任务的文件。
- 旧任务与已有 Codex thread 保留原共享目录，不自动搬家。新的目录结构便于之后按任务归档、清理；本版尚未增加归档或删除按钮。目录划分用于组织文件，不改变已配置的系统访问权限。

## English

- The APK includes approximately **25 MB** of local speech-model weights. Recognition runs on the device and needs neither an ASR account nor network access for recognition. Microphone permission is still required.
- Hold the voice button to record and release it to finalize. During recognition, the UI displays cumulative interim text; each later partial replaces the previous partial, and the user can edit the draft. Final text only fills the draft and is never sent automatically. Editing the draft, changing tasks, cancelling, or leaving the page prevents late recognition results from overwriting current text.
- Recognition quality depends on the bundled small model and may include errors or omissions. Users can correct interim text in the UI, but semantic correction is not guaranteed. DeepSeek receives text only after the user explicitly sends the draft; speech audio is not sent directly to DeepSeek as task input.
- The first build downloads script-pinned AAR resources (about 49 MB) and a model archive (about 21 MB), then caches them at the location configured by `DAXQO_VOICE_CACHE`. Build-time downloads do not mean runtime recognition needs a network connection.
- GUI workspace artifact cards, authorized raster-image previews, file opening, and remote-email attachment boundaries continue from the [V0.6.1 record](V0.6.md). Its device failure notes remain historical and do not report this version's microphone result.

### Touch controls and task workspaces

- Android uses a 48×48 CSS-pixel microphone target and an overlay status hint. Holding, loading, growing interim text, completion and cancellation do not move the button. Android hides the Enter hint; desktop keyboard hints remain available.
- New tasks use `workspace/tasks/<task UUID>/`. Follow-ups, resumes and delegated work reuse that task directory. Email and scheduled tasks use the same allocation path. Task details offer a files shortcut, while the global file browser still lists all files.
- Uploaded originals remain in the staging area; each task receives an `inputs/` copy. Artifact links, image previews and email attachments resolve within the task directory, so same-named outputs from another new task are not selected.
- Existing tasks and saved Codex threads retain their original shared directory. The directory structure supports later per-task archiving and cleanup; this version does not add archive/delete buttons. Directory organization does not change configured system permissions.

### Verification status

- Six host test suites have passed.
- Core builds and lint have passed for both Android profiles.
- Chrome GUI regression has passed for voice drafts and retained image DOM behavior.
- **Real-microphone recognition passed on 2026-10-25** on STEPX Neo and Redmi K70 (Android 16), using combined versionCode 16 builds that retain Collector/Motor. Ordinary Chinese speech played through the computer speaker was captured by each phone microphone; no transcript was injected. Both updated the draft while held, finalized on release, stopped microphone capture, and created no task automatically.
- Early release on Neo stopped later words from being appended. Cancellation on K70 restored the original empty draft and ignored later speech. Chrome regression separately covers draft-range replacement, revised cumulative hypotheses, manual edits, late callbacks, pointer ownership and keyboard hold/release.
- The sample requested opening a folder and viewing a generated image. Both phones produced the complete wording without automatic punctuation in one run; another Neo run misrecognized “输入” as “收入”. This functional check is not an accuracy benchmark for accents, noise or extended sessions. On first hold, wait for the listening prompt while the model loads.
- Core and combined builds passed build/lint and six host suites for both profiles. Windows backend/script suites passed with conditional platform-related skips; on-phone Linux update tests passed.
